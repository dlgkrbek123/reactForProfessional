재조정: 현재 DOM과 예상되는 다음 DOM을 일치시키는 과정

가상 DOM은 UI 상태의 청사진
리턴된 리액트 엘리먼트가 트리를 구성

---------------------------------------------------------------------------------------------

구버전의 리액트는 스택기반의 재조정자를 사용했다.
간단한 경우에는 잘 동작했지만 APP 규모가 커지면서 문제가 생김

순차적으로 변경사항을 리렌더링
- 무거운 컴포넌트 리렌더링이 사용자 입력등을 blocking
- 사용자 입력의 우선순위를 높이고 진행중인 리렌더링을 멈출 수 있어야하고 리렌더링간의 우선순위를 지정할 수 있어야 하는데...
- 스택 기반의 재조정자는 우선순위를 설정하지 않음

- 업데이트를 중단하거나 취소할 수 없음

끊김현상과 느린 응답속도

---------------------------------------------------------------------------------------------

파이버 재조정자
- 파이버 트리를 기반으로 업데이트의 우선순위를 정하고 동시실행하여 향상된 성능의 재조정을 실행

파이버
- 조정자를 위한 작업단위를 나타내는 자료구조
- ReactElement에서 생성되며 상태를 저장
- 특정 시점에 존재하는 실제 컴포넌트 트리를 나타냄

- 컴포넌트 인스턴스와 그 상태를 표현
- props + state + children을 포함
- 트리내의 위치 + 업데이트 우선순위와 관련된 메타데이터

- createFiberFromTypeAndProps로 리액트 엘리먼트에서 파이버를 산출

더블 버퍼링
- 화면밖에서 다음 화면을 준비한 다음 반영
- 현재 파이버를 포함하는 트리 / 작업용 파이버를 포함하는 트리



재조정은 렌더링 단계 => 커밋 단계로 구성됨
- 단계를 나눔으로써 우선순위가 더 높은 새로운 업데이트가 있다면 tree를 폐기 가능
- 일시 정지했다가 다시 시작이 가능

1. 렌더링
- 상태 변경시 시작되어 현재 파이버트리를 fork
- 위에서 아래로 이동하며 컴포넌트에 dirty 플래그 지정 (beginWork)
- 커밋하기 위한 작업용 트리에 있는 파이버 노드에 변경을 적용 (completeWork)

2. 커밋
- 렌더링 단계에서 가상 DOM에 적용된 변경사항을 실제 DOM에 반영
- 작업용 파이버트리가 호스트 환경에 커밋되고 작업용 트리가 현재 트리로 전이됨

- 변형 단계
  - 작업용 트리의 파이버노드에 적용된 업데이트를 실제 DOM에 반영

- 레이아웃 단계
  - DOM에서 업데이트된 노드의 새 레이아웃을 계산 

커밋단계에서 sideEffect가 실행됨 
- batch: 새컴포넌트가 DOM에 추가시
- update: 컴포넌트의 props / state가 업데이트 될때
- delete: 컴포넌트가 DOM에서 제거될때
- layout : 페인트 가능 시점전에 발생하여 페이지 레이아웃을 업데이트

스케줄러는 5ms마다 실행을 메인스레드로 제어를 반환

재조정과정에서 여러개의 가상 DOM 업데이트를 한번의 DOM업데이트로 결합하여 일괄 처리하는 최적화를 거친다.

const Example = () => {
  const [count, setCount] = useState(0)

  const handleClick = () => {
    // 실제 DOM을 한번만 업데이트
    setCount(prev => prev + 1);
    setCount(prev => prev + 1);
    setCount(prev => prev + 1);
  }

  return (
    <div>
      <p>카운트: {count}</p>
      <button onClick={}>증가</button>
    </div>
  )
}
