hydration
- 사전렌더링된 html에 이벤트리스너 및 js기능을 추가하는 프로세스
  - 사전렌더링된 html은 js가 적용되지 않은 상태여서 상호작용이 안됨
  - 상호작용을 추가

1. bundle load
2. 이벤트 리스너와 동적기능을 DOM요소에 추가

react-dom의 hydrateRoot함수를 실행하여 수행
- root컴포넌트와 DOM컨테이너를 전달받음

hydration되면서 HTML구조와 ReactElement의 구조와 일치되어야 함
- 일치되지 않으면 동적기능을 올바르게 연결할 수 없음

renderToString
- 리액트에서 제공하는 서버사이드 렌더링 API
- 리액트 컴포넌트를 HTML문자열로 렌더링할때 사용
- 동기식으로 작동 / html문자열을 리턴
  - 컴포넌트가 깊거나 요청이 많다면 시간이 꽤 소요되고 과부하를 야기할지도
  - 이벤트 루프를 차단
- 스트리밍을 지원하지 않아 전체 html문자열을 생성해야함

JSX -> React.createElement -> React Element -> renderToString() -> html

renderToPipeableStream
- 대규모 앱을 NodeJS 스트림에 렌더링 하는 방식
- 응답 객체로 파이프할수 있는 스트림을 리턴
- 동시성 기능 / Suspense

- 스트림을 활용하여 전체데이터를 메모리에 올리지 않고 점진적인 chunk로 처리

- Suspense가 해결되면 들어갈 위치를 마킹
  - Suspense fallback을 서버에서 렌더링한 컴포넌트로 대체ㄹ

Nodejs 스트림
- 데이터가 출발지에서 목적지로 흐르는 "흐름"
- 메모리를 효율적으로 처리할 수 있는 강력한 추상화기능을 제공

1. 읽기 가능 스트림: 읽을 수 있는 데이터 출처 (파일읽기/데이터수신)
2. 쓰기 가능 스트림: 데이터를 쓸 수 있는 대상 (write -> end)
3. 양방향 스트림: 읽기도 되고 쓰기도 가능한 스트림(소켓이나 통신 채널) 
4. 변환 스트림: 데이터가 흐르는 동안 데이터 변환을 수행하는 특수한 양방향 스트림 (압축/해제)

서로다른 두개의 스트림을 연결하는걸 pipe한다고 함

브라우저에는 ReadableSream이 있다.
- 프로미스 기반이라 이벤트기반인 Nodejs와는 좀 다름

const readableStream = new ReadableStream({
  start(controller) {
    controller.enqueue("Hello");
    controller.enqueue("World");
    controller.close()
  }
})

const reader = readableStream.getReader();

async function readAllChunks(streamReader) {
  let result = "";

  while(true) {
    const { done, value } = await streamReader.read();
    if(done)break;

    result += value;
  }

  return result;
}

readAllChunks(reader).then((text) => {
  console.log(text);
})
