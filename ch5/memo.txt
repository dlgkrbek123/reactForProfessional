memoization: 이전에 계산된 결과를 캐싱해서 최적화하는 기법
- 입력을 기준으로 출력값을 기억
- 재접근시 캐싱된 값을 반환
- 함수의 순수성을 기반으로 함(입력이 같으면 출력이 같음이 보장되어야 함)

---------------------------------------------------------------------------------------------

react에서는 React.memo를 통해 props가 변경된 경우에만 리렌더링되게 처리가능
- 재조정과정에서 다시 호출되지 않음
- 성능향상에 기여

- 부모가 리렌더링 되면 재조정과정에서 하위 트리에 있는 컴포넌트를 재호출하는것이 리액트의 기본
  - props가 동일해도 함수는 호출되고 렌더링된다.
  - 근데 실제 props는 변경이 안되었다면 굳이 호출할 필요는 없음

---------------------------------------------------------------------------------------------

React.memo는 기본적으로 얕은 비교를 수행해 props의 변경여부를 확인
- primitive type은 잘 비교하는데 객체 타입은??
  - primitive type은 불변이라 새로운 값을 만들지 않고는 변경을 못함
  - 객체타입은 메모리 상 주소가 저장
    - 비교연산은 참조 기반으로 수행

props의 일부항목이 참조타입이라면 React.memo걸어도 리렌더링 될 수 있다.
- 특히 파생값이라면 문제가 쉽게 재현 / 파생값도 useMemo를 적용하던가
- 이벤트 핸들러 주고 받을때도 함수라서 쉽게 꺠짐 / useCallback

props가 바뀌었다고 판단하거나 state, context 변경은 리렌더링된다.

---------------------------------------------------------------------------------------------

React.memo는 컴포넌트 자체를 메모화하여 렌더링을 막음
useMemo는 컴포넌트 내부의 특정 연산을 메모화
- 재계산을 회피
- 정렬같이 무거운 연산

메모아이제이션이 항상 좋은건 아니다.
- 메모리 공간도 먹고...
- 비교도 해야하므로...

---------------------------------------------------------------------------------------------

리액트 컴파일러는 메모화를 자동으로 해준다고 한다.
- 객체 동일성 비교를 깊은 비교없는 시맨틱 값 비교로 변환한다고 함
