동기식 렌더링 문제점
- 메인스레드를 blocking해서 사용자 경험이 저하됨 (성능과 반응성)
- 우선순위 개념이 없다.

---------------------------------------------------------------------------------------------

동시성 렌더링은 업데이트 작업의 우선순위를 부여하고 
우선순위가 높은 업데이트가 낮은 업데이트에 의해 가로막히지 않게 처리

응답성을 유지 => 사용자 경험 개선
렌더링을 작은 덩어리로 분할해 점진적 처리 => 중지가능성 추가

---------------------------------------------------------------------------------------------

파이버 재조정자
- 응답성과 성능을 개선
- 렌더링 프로세스를 파이버라는 작고 관리하기 쉬운 작업단위로 분할해 처리
- 렌더링 작업을 중지 / 재개 / 우선순위 부여

---------------------------------------------------------------------------------------------

- 렌더레인을 통해하는 리렌더링은 동기적으로 DOM을 업데이트
- 렌더링 우선순위를 낮추려면 useTransition hooks를 활용 (지연시키기)

const [isPending, startTransition] = useTransition();

startTransition(() => {
  setMessages([...])
})
// 이로 인해 form-input의 우선순위가 높아져 반응성 유지


파이버 재조정자는 스케쥴러를 활용
- 스케줄러는 microTask를 예약해서 메인 스레드의 제어를 관리 (함수 실행을 예약하는 시스템)
  - 렌더 레인을 통해 우선순위 설정
  - lane이 sync면 즉각적인 처리를 위해 마이크로태스크를 대기열에 추가
  - sync가 아니라면 콜백을 예약하고 다음 레인을 처리

---------------------------------------------------------------------------------------------

렌더 레인
- 작업의 렌더링과 우선순위 관리
- 렌더링 주기에서 처리할 수 있는 작업
- 여러개의 우선순위를 나타내는 레인이 있다.

setState호출시 업데이트가 레인에 추가

- 한 레인 내부의 업데이트는 일괄처리된다.
- 업데이트 처리후 커밋 단계로 진입하여 변경사항을 DOM에 적용하고 effect실행 후 마무리

우선순위 결정은 아래와 같이 수행
- context평가 (사용자 상호작용인지? state/props변경인지? 서버응답에 의한것인지 평가)
- useTransition, useDeferredValue와 연루되었는지?

---------------------------------------------------------------------------------------------

useTransition
- startTransition으로 감싸진 모든 업데이트를 트랜지션 레인에 할당되게 함
- isPending : 트랜지션이 진행중인지
- startTransition : 지연되거나 낮은우선순위가 부여되어야 하는 업데이트를 감쌈

---------------------------------------------------------------------------------------------

useDeferredValue
- 특정 UI 업데이트의 렌더링을 지연시키기
- 새값으로 업데이트할 시점을 제어

const [searchValue, setSearchValue] = useState("") 
const useDeferredValue = useDeferredValue(searchValue)

- 지연된 렌더링을 중단 가능
  - 우선순위 더 높은 애가 발생시 중단되며 백그라운드에서 다시 진행

---------------------------------------------------------------------------------------------

동시성 모드는 성능과 응답성을 높였지만 새로운 문제도 만듦
- 업데이트 처리 순서를 예측하기 어려움

티어링 : 업데이트 순서가 어긋나면서 UI가 일관성을 잃을 수 있다.
- 동기식 렌더링할때는 순서가 보장되어 일관성이 항상 유지됨 (컴포넌트는 최신 상태를 기준으로 렌더링)

useSyncExternalStore
- 애플리케이션의 내부 상태와 외부상태를 동기화하는 hooks
- 외부 저장소에 변화가 발생시 동기적으로 업데이트를 강제해 일관성을 유지

useSyncExternalStore(() => {}, getSnapShot)

- getSnapshot: 외부 저장소의 현재값을 리턴

---------------------------------------------------------------------------------------------

이벤트 루프
- 콜백 실행등 수행할 작업이 있는지 확인
- 매크로 태스크 큐와 마이크로 태스크 큐라는 2가지 대기열

매크로 태스크 큐
- 이벤트 처리, setTimeout, setinterval, 입출력 수행등의 작업이 저장되는 곳
- 한번에 하나씩 처리되며 하나가 완료되어야 다음작업을 처리

마이크로태스크 큐
- 더 작고 즉각적인 작업
- Promise, Object.observe, mutationObserver같은 연산

마이크로 태스크 큐의 우선순위가 높아서 다음 매크로 태스크로 넘어가기전에 실행
마이크로 태스크가 계속 추가되면 매크로 태스크 큐는 실행 못함
