DOM (문서 객체 모델)
- HTML문서를 JS객체로 모델링
- 브라우저 런타임 문서 모델

브라우저는 HTML의 구문을 분석해 DOM 트리로 변환

실제 DOM 조작시querySelector로 검색
- 전체문서트리에서 검색하는데 문서가 크다면 찾는데 검색이 오래걸릴 수 있다.

DOM을 실제 조작시 조작시마다 레이아웃 재계산 / 다시 그리는 과정이 진행됨
- 느리며 비용이 많이 든다.

레이아웃 쓰래싱 : 레이아웃 속성을 읽고 쓰는 행위가 자주 반복되어 발생하는 불필요한 레이아웃 재계산
- 특정 속성은 읽기만 해도 reflow를 수행 (dom.offsetWidth)
- 읽기와 쓰기 작업을 종류별로 나눠 일괄 처리하여 이런 부작용을 줄여야 한다.

reflow / repaint

---------------------------------------------------------------------------------------------

실제 DOM이 업데이트될때마다 reflow, repaint의 무거운 작업을 수행

documentFragment
- DOM을 저장하는 가벼운 컨테이너
- 원본 DOM에 영향을 주지 않고 업데이트를 수행할 수 있는 임시저장소
- 업데이트 완료후 documentFragment를 DOM에 추가하여 reflow / repaint를 한번만 발생

리스트 아이템을 100개 추가할때 직접 appendChild하지 말고 documentFragment로 한번만 업데이트되게 처리

const fragment = document.createDocumentFragment();
for(let i=0; i<100;i++) {
  const li = document.createElement('li')
  li.textContent = `${i+1}`
  fragment.appendChild(fragment);
}
document.getElementById("list").appendChild(fragment)

실제 DOM은 노드 객체로 구성
가상 DOM은 평범한 JS Object로 구성 

가상 DOM 업데이트는 실제 페이지 레이아웃과 무관하여 빠르게 동작
- 비교 알고리즘으로 차이점을 식별
- 실제 DOM 업데이트에 필요한 최소 변경사항을 산출하여 적용

재조정
- props, state 변경시 가상 DOM이 먼저 업데이트
- 이전 가상 DOM트리와 비교하고 변경점을 계산하는 작업

메모링에 실제 DOM과 매핑되는 가상 DOM 트리 생성

ReactElement
- 가상 DOM트리를 이루는 단위
- 평범한 JS Object
- 화면에 표시할 내용을 표현
  - props
  - attribute
- type은 문자열인 경수 host 컴포넌트, 함수인 경우 사용자 정의 컴포넌트를 의미

---------------------------------------------------------------------------------------------

리액트 컴포넌트는 state나 props의 변경을 감지하면 해당 컴포넌트와 자식 요소를 리렌더링
- 재귀적으로 자식들도 재호출된다.
- 그런데 props가 변경되지 않은 자식 요소돌 다시 리렌더링됨
  - 리액트는 컴포넌트와 데이터 종속성 관계성을 모르기 때문에 UI 일관성을 유지하기 위해 모든 컴포넌트를 리렌더링
- memo와 useMemo로 최적화
